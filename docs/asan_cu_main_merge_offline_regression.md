# CU main() 점포 병합 로직 오프라인 회귀 검증

검토일: 2026-10-13. 브랜치: `permission-test-20261013-cu`.
운영 원본: `cu_stock_monitor.py` (GitHub SHA `709029c9a94dc459b440e1b570c61770055de5be`, 읽기 전용).
추가 테스트: `tests/test_cu_main_merge_ast_offline.py`.

## 검증 방법

GitHub 원본 `main()`의 `for item in stores` 병합 블록을 읽고 해당 구문을 격리한 Python AST 사본을 ChatGPT Python 환경에서 실행했다. **main() 자체, query(), telegram(), save_state()는 호출하지 않았다.** 합성 데이터 7개 시나리오에서 7 PASS / 0 FAIL / 0 ERROR (0.001초).

작업 브랜치에 추가한 테스트 파일은 원본 `cu_stock_monitor.py`에서 **AST를 직접 추출하여 컴파일**하도록 작성했다. 단, **GitHub에 커밋한 파일 자체의 테스트 실행은 수행하지 않았다.** 따라서 실행 결과는 확인한 병합 코드 조각에 대한 검증이며 원본 전체를 import한 회귀 테스트의 통과를 의미하지 않는다.

## 시나리오별 결과

| 시나리오 | 확인한 현재 동작 |
|---|---|
| 동일 코드·동일 수량 | 첫 레코드 유지, 중복 수량 합산 없음 |
| 동일 코드·상충 수량 | `conflicts` 추가, `observed`에서 제거 |
| 충돌 후 같은 코드 재등장 | 재등록하지 않음 |
| 동일 코드·다른 점포명/주소·같은 수량/도시 | **첫 레코드 유지, 충돌 표시 없음** |
| 동일 코드·다른 도시 | 충돌로 제외 |
| 미관측 코드 | `observed`에 없음. 0으로 만들지 않음 |
| 다른 점포 코드 | 각각 독립 유지 |

## 발견한 위험과 제한

1. 동일 코드의 **이름 또는 주소 불일치**는 현재 충돌 조건에 포함되지 않는다. 점포 정체성 검증이 필요한 별도 개선 과제이며 이번에는 운영 코드 수정 금지.
2. 미관측은 이 병합 딕셔너리에서의 부재를 뜻할 뿐, 실제 API 커버리지 또는 최종 `NOT_OBSERVED` 상태 분류를 검증한 것은 아니다.
3. `query()`의 필터, 저장, 알림, 설정 및 네트워크 경로는 이 테스트의 범위 밖이다.
4. 새 테스트의 `ast.walk` 기반 루프 선택은 소스 구조 변경 시 실패하도록 설계됐다. 추후 체크아웃된 원본에서 실행 검증 필요.

## 실행 안전성

실제 CU API 호출, 텔레그램 발송, GitHub Actions 실행, 운영 상태 파일 변경, 운영 `main()` 호출, `main` 브랜치 변경 없음. 작업 브랜치에 독립 테스트 파일과 이 보고서만 추가.
