# CU 동일 점포 코드의 이름·주소 충돌 격리 정책 (오프라인 제안)

검토일: 2026-10-13. 브랜치: `permission-test-20261013-cu`.
운영 원본 `cu_stock_monitor.py`는 변경하지 않음. 정책 초안 `tests/cu_strict_identity_policy.py`, 합성 테스트 `tests/test_cu_strict_identity_policy.py`.

## 기존 운영 동작과 제안의 차이

현재 `main()`의 점포 병합은 동일 코드에서 **재고 또는 도시가 다를 때만** 충돌로 처리함. 같은 코드·같은 재고·같은 도시이지만 이름이나 주소가 달라지는 경우는 첫 레코드가 유지될 수 있음. 제안은 이 경우도 해당 관측 주기 전체에서 격리하는 **fail-closed** 방식임.

## 보수적 판정 기준

| 관측 | 제안 판정 |
|---|---|
| 코드, 수량, 도시, 이름, 주소 모두 일치 | 중복 1건만 인정 |
| 수량 다름 | STOCK_CONFLICT: 제외 |
| 도시 다름 | CITY_CONFLICT: 제외 |
| 이름 다름 | NAME_CONFLICT: 제외 |
| 주소 다름 | ADDRESS_CONFLICT: 제외 |
| 이름/주소/도시 누락 | MISSING_IDENTITY: 제외 |
| 코드가 숫자 문자열이 아님 | INVALID_CODE: 제외 |
| 재고가 음수·정수가 아님 | INVALID_STOCK: 제외 |
| 미관측 | 기록하지 않음; 재고 0으로 해석 금지 |

한 코드에서 여러 충돌이 동시에 발생하면 모든 이유를 보존. 충돌된 코드는 동일 관측 주기 내 다시 등장해도 자동 재진입 불가. 알림이나 상태 갱신의 입력에서 격리하는 방안을 권장.

## 정규화 경계

유니코드 NFKC와 연속 공백 축약·앞뒤 공백 제거만 허용. 도로명 변환, 행정구역 추정, 점포명 접두어 제거, 숫자·호수 교정, 개명 추론은 금지. 이 때문에 표현이 실질적으로 같아도 보수적으로 격리될 수 있음. 공식 CU 점포 식별 근거가 있으면 별도 검토 후 수동 승인.

## 테스트 및 한계

12개 합성 사례(동일 중복, 수량·이름·주소·도시 충돌, 복합 충돌, 정규화, 충돌 재진입 금지, 누락·무효 입력, 미관측, 다른 코드)를 격리된 Python 환경에서 동일 로직의 사본으로 실행하여 **12 PASS / 0 FAIL / 0 ERROR**. 실제 GitHub에 커밋된 두 파일을 원격 실행한 것은 아님. 이 정책은 현재 운영 코드에 적용되지 않았으며, 실제 API 응답의 이름·주소 정확도나 API 검색 범위도 검증하지 않음.

## 향후 운영 적용을 위한 별도 승인 게이트

1. CU 공식 근거와 실제 과거 기록을 이용해 이름·주소 표기 변형의 오탐 격리율을 오프라인 분석.
2. 원본 모니터와 제안 정책의 동일 fixture 처리 결과 비교.
3. 격리 사유·입력 출처·검색 좌표·시각을 기록하되 개인정보/비밀키 제외.
4. 격리 건은 **알림 및 상태 저장에 반영하지 않고**, 관측 누락은 0으로 전환하지 않음.
5. 별도 사용자 승인 전까지 운영 코드 수정, API 호출, Telegram 발송, Actions 실행, main 브랜치 변경 금지.
