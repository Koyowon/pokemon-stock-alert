# CU 아산 제한적 API 검증 — 사전 승인용 안전 테스트 명세

기준일: 2026-10-13. 범위: `permission-test-20261013-cu`, 바코드 `8800286275732`, 아산 후보 119개, 검색 좌표 7개.
**이 문서는 실제 API 실행 승인이나 운영 변경 승인이 아니다.** `tests/test_cu_api_contract_offline.py`는 합성 fixture만 사용하는 독립 테스트이며 실제 API/운영 모니터 통합 테스트가 아니다.

## 현재 코드에서 확인한 사항

- `cu_stock_monitor.py`: 아산 검색점 7개, 요청 파라미터 `size=100`, `offset=0`, `storeCheck=true`, 바코드 `8800286275732` 검증. **size=100이 실제 반환 상한이라는 보장은 없음**. 반복 페이지 요청 구현 없음.
- API `success=true`, 상품 코드 일치, 숫자형 점포 코드, 유효한 재고값을 필터링. 잘못된 응답은 오류 또는 무시될 수 있으므로 실제 응답 형태 확인 필요.
- 중복 점포 코드의 동일 수량은 중복 합산하지 않으며 수량이 충돌하면 제외하는 로직 존재. 코드 외 점포명/주소 불일치까지 검사하지는 않음.
- `cu_asan_registry.py`는 미조회 `NOT_QUERIED`, 성공 조회 후 미관측 `NOT_OBSERVED`, 명시적 0 `ZERO_STOCK`을 구분. 단, 조회 성공이 119개 점포 모두의 지리적 범위 포함을 뜻하지 않음.
- 운영 `main()`은 상태 파일 저장 및 Telegram 발송 경로를 포함하므로 **실제 테스트에서 직접 실행 금지**.

## 향후 승인 전 준비 사항

1. 실조회 여부를 **별도로 명시 승인**받는다. 승인 시 테스트 좌표, 호출 상한, 시간, 타임아웃, 요청 간격, 데이터 보관, 중단 조건을 확정한다. 이 문서에 임의의 호출 횟수·반경을 설정하지 않는다.
2. API 응답을 별도 격리 fixture로 캡처할 수 있는지와 서비스 이용 조건을 먼저 확인한다. 개인정보·비밀키·인증정보를 fixture에 저장하지 않는다.
3. 테스트용 모듈에서 외부 요청 함수는 명시적 주입 방식으로만 호출하고, 운영 `main()`은 호출하지 않는다. Telegram·상태 저장은 거부 함수로 바꿔 호출 시 즉시 실패시킨다.
4. 실패·시간초과·부분응답·빈 응답·반환 포화·동일 점포 중복·상충 수량·잘못된 바코드·잘못된 코드·지역 혼입을 각각 재현한다.
5. 관측되지 않은 91개 미확인 코드 후보는 코드 추정 금지. 116개 좌표 미확보 후보는 거리 및 커버리지 미확정으로 남긴다.
6. 모든 판정 결과에 근거 응답 식별자·검색 좌표·요청/응답 상태·실행 시각을 기록한다. 점포별 관측이 없는 경우 119/119 커버리지 주장을 금지한다.
7. 통과 이후에도 검색 좌표 증설·운영 배포·텔레그램 활성화는 **별도 사용자 승인**이 필요하다.

## 오프라인 fixture 테스트 실행 (운영 작업 아님)

```bash
python -m unittest discover -s tests -p 'test_cu_api_contract_offline.py' -v
```

합성 테스트는 계약의 안전한 처리 방식을 예시로 검증할 뿐, 현재 `cu_stock_monitor.py`와 실제 CU API가 이를 모두 충족한다는 증거는 아니다. 특히 fixture의 `declared_total`은 **가상 메타데이터**이며 실제 CU 응답에 존재한다고 가정하지 않는다. 합성 fixture의 pagination PASS도 실제 페이지 지원 확인과 무관하다.
