공식 점포 검색 화면은 점포명·주소 확인 경로를 제공하지만 이번 공개 웹 결과에서는 **재고 API용 내부 숫자 점포 코드와 해당 점포명·주소가 함께 검증되는 원천 기록을 얻지 못함**. 전화번호, 매장 URL의 숫자, 지도 식별자 등은 재고 API 점포코드로 취급하지 않는다.

## 증거 수집
1. 공식 점포 검색에서 점포명·도로명 주소를 확인하고 URL·확인일을 기록한다.
2. 동일 점포에 연결되는 **실제 재고 API 점포코드**를 신뢰할 수 있는 동일 출처 자료에서 확인한다. 현재 금지된 실 API 호출은 하지 않는다. 공식 사업자/고객센터에 점포코드 공개 가능 여부를 문의하는 방법은 있으나 답변이 오기 전에는 미확인이다.
3. `docs/store_code_evidence_intake_template_20261014.csv`에 확인된 증거만 입력한다. 열: `chain,registry_id,store_code,name,address,source_url,observed_at,barcode`. CU는 기존 `ASAN-CU-...` 후보 ID, 이마트24 제주는 빈 후보 ID를 허용.
4. 오프라인에서 `python tests/offline_store_evidence_intake_v2.py docs/<evidence>.csv` 실행. 출력은 수동 검토 상태만 제공하며 운영 점포코드 자동 등록 없음.
5. 기존 코드 충돌, 잘못된 바코드, CU 점포명·주소 불일치, 제주 이외 주소, 중복 제출을 차단한다. `MANUAL_REVIEW_REQUIRED`도 실제 검증 완료나 운영 반영 승인을 뜻하지 않는다.
6. 동일 주소에 서로 다른 CU 후보가 있으면 각 점포의 독립적인 점포코드·출처 확인 전까지 합치거나 배정하지 않는다.

## 검증과 한계
- 로컬 격리 환경에서 동일 검증 규칙의 선행 구현을 Python unittest로 **11개 테스트 통과** 확인.
- GitHub에 추가된 `tests/offline_store_evidence_intake_v2.py`와 `tests/test_offline_store_evidence_intake_v2.py`는 원격 브랜치에서 직접 실행하지 않았음. CI 통과라고 주장하지 않음.
- 단순 문자열 정규화와 URL 형식 검사는 **실제 출처의 진위**를 보증하지 않는다. 사람이 공식 자료 원본을 재확인해야 한다.
- 공개 웹 검색으로는 실시간 점포 영업 상태, 점포 목록의 전수성, API 재고 조회 성공을 증명할 수 없음.
