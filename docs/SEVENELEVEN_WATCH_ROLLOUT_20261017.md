# 세븐일레븐 미확인·누락 점포 운영 감시 승인안

## 범위

기존 제3자 API 검색 결과에서 주소로 확인한 남원 17, 아산 99, 전주 135개 점포(합계 251개)를 감시 목록으로 고정한다. 공식 전체 점포 수를 보장하는 목록이 아니다. 기존 점포코드·매장명·주소를 보존한다. 최초 실행은 전체 점포를 미확인으로 시작하며 과거 진단 수량을 현재 운영 수량으로 복사하지 않는다.

기존 CU·GS25·이마트24 감시, 공통 제어 설정, 웹페이지 및 Telegram 알림에는 손대지 않는 별도 **조회 상태 감시**다. 재입고 알림 연동은 포함하지 않는다. Telegram 비밀값도 사용하지 않는다.

## 실행과 호출 제한

승인 후 main에 반영하면 GitHub Actions가 5분 간격으로 실행을 요청한다. GitHub 스케줄 지연 가능성이 있으므로 정확한 5분 실행은 보장하지 않는다. 다른 브랜치에서 수동 실행해도 작업 본문은 실행되지 않는다. 이번 준비 과정에서는 Actions 또는 실제 API를 실행하지 않았다.

매 실행 지역 전체 재고 조회 최대 3회와 지역별 미확인 점포 개별 조회 최대 1회씩, 총 최대 6회다. 지역 시작 순서를 순환하고 개별 조회는 마지막 개별 조회가 가장 오래된 점포부터 진행한다. 점포 응답에는 상품 바코드·상품명·점포코드·매장명·주소 검증을 적용한다. 지역 응답 수치가 100이더라도 135개 등록 목록에서 빠진 점포를 미확인으로 남긴다. 개별 응답은 해당 점포에만 적용한다.

연속 요청 오류 2회면 중단한다. 400/401/403/404/429는 1회 즉시 중단하고, 리디렉션을 따르지 않는다. 자동 재시도는 없다. 오류는 외부 서비스의 구체 원인으로 단정하지 않는다. 개별 점포 실패 후 재시도 대기는 15분에서 최대 6시간까지 늘어난다. 다른 점포는 순환 순서대로 계속 감시한다. 동일 점포가 지역 전체 응답에서 회복되면 대기를 초기화한다.

요청 간 2초 간격, 응답 최대 1MB, 소켓 타임아웃 20초, 요청 시작 예산 180초를 적용한다. 소켓 타임아웃은 총 실행시간 제한이 아니므로 워크플로 프로세스에 210초 제한(+종료 유예 5초)을 추가했다. 시간 초과·코드 실패 시 상태 저장 단계를 실행하지 않고 기존 상태를 보존한다.

개별 조회는 지역당 실행당 1곳으로 제한되므로 모든 미확인 점포를 매 5분마다 개별 조회하는 것은 아니다. 전주 미확인 129곳은 실패/지연이 없다 해도 전체 개별 조회 순환에 최소 약 10시간 45분이 필요하다. 지역 전체 조회는 실행마다 별도로 시도한다. 반복 장애가 있으면 더 오래 걸린다.

## 상태 및 관찰 방법

`seveneleven_watch_state.json`은 실행 성공 시에만 원자적으로 저장하고 이 파일만 운영 저장소에 커밋한다. 기존 다른 체인 상태는 변경하지 않는다. GitHub Actions Summary에는 지역별 감시/수량 확인/미확인 점포 수, 호출 수, 회로 중단 여부, 미확인 코드 목록을 제공한다.

점포별 `status`, 현재 `quantity`, `reason`, `checked_at`, `last_direct_at`, `direct_failures`, `next_direct_at`를 기록한다. 이전 확인 수량은 `last_known_quantity`, 확인 시각은 `last_success_at`로 별도 보존한다. HTTP 실패·응답 누락·-1·검증 실패는 UNKNOWN이며 현재 수량은 null이다. 수량 0은 검증된 실제 숫자 0에만 사용한다. 15분 이상 갱신되지 않은 결과도 현재 수량 미확인으로 돌리고 이전 수량만 보존한다. API의 숫자는 실물 재고 확인을 의미하지 않는다.

감시 대상 점포 삭제나 이름·주소 변경은 자동으로 승인하지 않는다. 현재 목록과 저장 상태가 달라지면 실행을 실패시켜 수동 검토한다. 신규점 자동 발견은 이번 범위 밖이다.

## 검증과 승인

실제 원본 응답을 이용한 251곳 유지, 전주 누락 35곳 보존, 502 전체 장애, 429 즉시 중단, 미확인 순환·대기, 이전 수량 보존, 잘못된 상품 차단, 시간 예산, 잘못된 점포 정체성 차단, 기본 CLI 무호출·무저장, 원자적 저장 실패 복구를 오프라인 검증했다. 기존 응답 계약 및 진단 테스트 포함 40개 통과.

별도 작업 브랜치에만 등록한다. main 반영과 스케줄 활성화는 최종 승인 후 진행한다. 이미 운영 중인 기존 재고 모니터는 변경하지 않는다. 중지하려면 이 워크플로를 비활성화하거나 schedule 항목을 제거하면 된다.
