결론: 남원 응답 계약과 17개 점포 동일성은 검증했으나 아산·전주 공급자 오류 때문에 3개 지역 전체 운영 반영은 승인 보류다. 이 브랜치는 진단·응답 검증 모듈이며 운영 모니터가 아니다. 정상 연결 완료나 정기 감시 활성화로 표시하지 않는다.

## 이번 실제 조회

이전 승인된 3건과 별도로, 확대 승인 후 API 요청 6건을 수행했다. 남원 매장/재고와 아산 매장 3건 성공, 아산 재고 timeout/HTTP 502 및 전주 매장 HTTP 502로 3건 실패했다. 아산 timeout 후 timeout을 15초에서 40초로 늘려 한 번 재확인했으나 HTTP 502였다. 연속 실패 3건 뒤 추가 호출을 중단했다. 전주 재고는 매장 조회 실패로 요청하지 않았다. 오류 상태는 서비스가 내놓은 결과이고 서버 원인/허용 한도/전체 장애 여부는 확인하지 못했다.

| 남원시 | 검색 결과 20개 중 주소가 남원시인 17개 | 17개 코드·매장명·주소 모두 목록과 일치 | 숫자 0개 응답 12곳·미확인(-1) 5곳 |

남원 검색 결과에 포함된 제주 남원읍 매장 3개는 주소 접두어로 제외했다. 남원 17개는 이 제3자 API가 반환한 범위의 완전성 확인이며, 전국 공식 매장 DB와 비교해 남원 전체 점포 수를 독립 검증한 것은 아니다. 12곳의 0개는 제3자 API 조회 시각의 응답이지 매장에 직접 확인한 수량이 아니다.

## 처리한 문제

seveneleven_contract.py를 추가해 실제 관찰된 JSON 필드만 읽는 순수 오프라인 검증기를 만들었다.

- 도/시 주소를 함께 검사하여 제주 남원읍·동명 지역을 제외한다.
- 매장 검색과 재고의 코드·매장명·주소가 모두 일치해야 수량을 인정한다.
- 상품코드 8800286275732 및 관찰된 상품명 비젼)포켓몬확장팩(30주년)_H를 대조한다.
- stockQuantity=-1·누락·null·bool·문자·소수는 UNKNOWN이다. isSoldOut=false나 집계 수량만으로 0을 만들지 않는다.
- 정확한 정수 0만 0으로 인정하고 성공 응답/stockAvailable/stockError를 함께 검사한다.
- 전체 건수와 반환 건수가 다르면 INCOMPLETE_PAGE로 차단한다. 아산 100/101을 정상 전체 조회로 오인하지 않는다.
- 코드 중복·동일 코드의 다른 주소/이름·다른 상품·공급자 실패는 차단한다. 운영 상태나 Telegram에 기록하지 않는다.

현재 웹 화면/Telegram/통합 설정에 세븐일레븐을 표시하거나 켜는 변경은 하지 않았다. 공급자가 실패한 지역을 임의 0개로 표시하는 반쪽 연동을 피하기 위해 기존 3개 편의점 운영과 분리했다.

## 운영 승인 판단

세 지역 전체 운영 활성화는 아직 승인할 단계가 아니다. 필요한 것은 아산 101개 전체 목록 확보 및 정상 재고 응답, 전주 정상 목록/재고 응답과 동일성 대조, 전체 범위/페이지 계약 확인이다. 제공자 문서 페이지 /prompt 및 홈도 이번 실행 환경에서 HTTP 403으로 본문을 가져오지 못했으며 접근 우회는 시도하지 않았다. 정상 응답을 확보하기 전 미검증 페이지 파라미터·숨은 앱 API·임의 좌표로 대체하지 않는다.

main 변경, 실제 Telegram 발송, Actions 실행, 운영 상태 저장은 하지 않았다. 승인된 읽기 전용 API 조회와 별도 브랜치 근거/검증 코드 저장만 했다. 외부 HTTP 502를 이 저장소의 코드 변경으로 해결했다고 주장하지 않는다.
