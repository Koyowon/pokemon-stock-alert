# 재고 현황판 감시 상태 연동

기존 `docs/stock/index.html`을 4개 브랜드의 조회 상태 기록과 연결했다. 공개 GitHub 저장 파일만 읽으며 실제 재고 API·Telegram·Actions를 수동 실행하지 않는다. 운영 모니터, 재고 기준 상태, 점포코드와 조회 예산은 변경하지 않는다.

## 표시 정책

- CU·이마트24·GS25는 각 `*_inventory_health.json`, 세븐일레븐은 `seveneleven_watch_state.json`을 현재 수량의 근거로 사용한다.
- 상품 코드·브랜드·스키마·감시 상태·숫자 형식과 시간 유효성을 검사한다. snapshot 생성 시각과 점포 상태 기록이 모두 15분 이내이고 정상 상태일 때만 현재 수량을 표시한다. 미래·누락된 시각, -1, 문자열, 불리언 등은 수량 0으로 해석하지 않는다.
- 기존 재고 기준 파일의 숫자는 과거 저장값으로만 사용한다. 현재 상태가 없거나 오래돼도 과거 수량을 현재 재고로 대체하지 않는다.
- 과거 수량은 ‘과거 저장 수량 보기’를 펼쳐서 확인한다. 확인 시각이 없으면 ‘확인 시각 미상’으로 표시한다. 마지막 수량 확인 시각은 상태 기록 시각·웹 파일 확인 시각과 별개다.
- 브랜드별 카드의 수량 확인/미확인/비활성 수는 화면에서 유효성을 검사한 결과를 다시 집계한다. JSON의 기존 summary를 무조건 신뢰하지 않는다. 1분마다 화면에서 만료 여부를 다시 계산하며 이 동작은 새 네트워크 요청을 만들지 않는다.
- 한 파일의 404·시간초과·읽기 실패가 다른 브랜드 표시를 막지 않는다. 이미 읽은 매장 목록은 유지하되, 실패한 현재 감시 파일의 수량은 미확인으로 처리한다. 최초 로드에서 목록과 상태가 모두 없으면 확인 가능한 점포만 표시하며 오류를 명시한다.

## 미확인 점포 원인 목록

통신·외부 오류, 응답에 없음·범위 미확정, 수량 미확인, 매장 정보 보류, 응답 검증 실패, 오래된 기록, 시각 오류, 상태 파일 오류 등으로 나눈다. `MISSING_IN_RESPONSE`만으로 좌표 조회 범위 밖임을 단정하지 않는다. 오래된 기록이 우선 표시돼도 점포 상세에서 원래 감시 사유 코드를 확인할 수 있다.

지역·브랜드·상태·원인 및 매장명/코드/주소를 조합해 필터링한다. 원인별 집계 버튼으로 해당 목록을 확인하고, 현재 필터에 해당하는 미확인 점포만 CSV로 내려받을 수 있다. CSV에는 코드, 주소, 사유, 시각, 이전 수량, 연속 미확인 실행 수가 포함된다. 문자열에 포함된 CSV 수식 시작 문자는 일반 텍스트로 처리한다.

CU 공식 확인 목록과 이전 관측 목록, 이마트24 저장 매장 목록, GS25 이전 관측 목록, 세븐일레븐 확인 목록을 유지한다. 전체 브랜드의 공식 전체 점포 조회 완료를 뜻하지 않는다. GS25 공식 전체 점포 수는 이 자료로 확인할 수 없다.

## 검증

`node --test tests/test_stock_health_model.cjs` : 19개 오프라인 테스트 통과.

정상 0, 미확인과 과거 수량 분리, 15분 경계, 파일/점포 시각 만료, 미래 시각, 상품/브랜드 오류, 무효 수량, 부분 파일 장애, 공식 CU 점포 유지, 세븐일레븐 정체성 불일치, 기존 이마트24 키 중복, 지역 오인 방지, 필터 조합, CSV 수식 방어, 잘못된 목록 구조의 독립 처리를 검증했다.

이 테스트는 외부 재고 서비스의 복구 또는 새 재고 수량 확보를 증명하지 않는다.
