# 편의점 재고 조회 상태 감시 운영 반영

2026-10-17 사용자 최종 승인으로 세븐일레븐 감시를 main 커밋 `6165d367e88e3aee83ad755acdd34dc34fa7c1b9`에 반영했다. 실제 API 수동 호출, Telegram 시험 발송, GitHub Actions 수동 실행은 하지 않았다. 스케줄 등록과 첫 운영 실행 성공 여부는 별개다.

## 세븐일레븐

`seveneleven-watch.yml`이 5분 간격 실행을 요청한다. 남원 17, 아산 99, 전주 135개 점포를 계속 유지하고 최대 6회 요청 예산 내에서 지역 조회 및 미확인 점포 순환 개별 조회를 진행한다. 자세한 제한과 상태 필드는 `SEVENELEVEN_WATCH_ROLLOUT_20261017.md`에 있다. 현재 적용 목록은 제3자 API에서 주소 대조를 통과한 251곳이며 공식 전체 매장 범위를 보장하지 않는다. 초기 운영 수량은 진단 데이터로 채우지 않는다.

## CU·이마트24·GS25

기존 각 브랜드 모니터가 실제 조회하면서 얻는 응답을 별도 상태 기록에 전달한다. 추가 API 요청·새 스케줄·새 재시도는 없다. 다음 기존 정기 조회에서 같은 점포를 다시 확인하므로 누락 점포는 삭제하지 않고 미확인으로 누적 추적한다. CU 좌표 조회 범위 밖에 있는 점포가 자동으로 개별 조회되는 기능은 아니다. 임의 좌표나 검증되지 않은 점포 조회 파라미터는 추가하지 않았다.

- CU: 공식 주소 대조 목록 377곳과 활성 지역의 이전 관측 점포를 감시 대상으로 삼는다. 현재 API에서 관측되지 않은 공식 점포는 미확인이다. 충돌·정체성 보류 점포도 수량 0으로 처리하지 않는다. 기존 점포 정체성 판정으로 이름·도로명 주소·층/호수 차이를 보수적으로 확인한다. 보류는 감시 기록의 미확인으로 남으며 기존 알림 로직은 바꾸지 않는다.
- 이마트24: 기존 모니터가 실제 감시하는 활성 지역 점포 목록을 사용한다. 배치 응답 누락·HTTP 실패·미조회·무효 수량의 기존 진단 사유를 점포별로 보존한다. 알림 전송 실패로 재고 기준 상태 갱신을 보류해도 조회 상태에는 정상 응답을 기록한다.
- GS25: 이전 관측 목록과 기존 코드가 검증한 이번 응답 목록을 유지한다. 부분 조회 실패 지역은 이번 수량이 확인됐다고 표시하지 않는다. 응답에서 빠진 이전 점포는 미확인이다. 기존 아산 승인 코드 필터를 유지한다. GS25는 공식 전체 점포 목록을 확보한 것이 아니므로 이 범위 밖 점포의 누락 감지는 보장하지 않는다.

기존 모니터의 호출 제한·회로 중단·재시도·알림·재고 기준 상태 저장은 보존한다. 추가 기능은 감시 결과의 관측성과 지속 기록이다. 전 브랜드의 공식 전체 매장 수집이나 응답 누락 원인의 해소를 뜻하지 않는다.

## 기록과 확인

- CU: `cu_inventory_health.json`
- 이마트24: `emart24_inventory_health.json`
- GS25: `gs25_inventory_health.json`
- 세븐일레븐: `seveneleven_watch_state.json`

이 파일들은 정상적으로 감시 코드를 실행한 다음 생성한다. 배포 시 운영 수량이나 건강 상태를 임의로 초기화하지 않았다. CU·이마트24·GS25는 기존 워크플로의 마지막 단계가 `always()` 조건으로 각 브랜드 건강 상태 파일만 별도로 커밋한다. 따라서 원래 조회 단계가 실패해도 가능한 범위에서 미확인 기록을 보존하고 GitHub Actions Summary에 집계·미확인 코드 목록·생성시각을 남긴다. 모니터 시작 전 실패 또는 강제 종료에서는 새 파일을 만들 수 없으며 워크플로 실패 상태와 마지막 생성시각을 함께 확인해야 한다. 저장/푸시 충돌이나 권한 오류는 워크플로에서 실패로 드러나며 성공으로 단정하지 않는다.

점포별 현재 `quantity`는 검증된 비음수 정수 응답일 때만 숫자다. 미확인 수량은 null이며 `status=UNKNOWN`, 비활성 점포는 `DISABLED`다. `reason`, `checked_at`, `unknown_runs`, `first_unknown_at`로 누락의 사유·시점·지속 횟수를 확인한다. 과거 확인 수량과 시각은 `last_known_quantity`, `last_success_at`로 별도 보존한다. 건강 상태 파일에서 읽은 값도 생성시각이 오래됐으면 현재 재고로 사용하면 안 된다.

각 건강 상태 파일은 알림 재고 기준 상태(`state.json`, `cu_stock_state.json`, `gs25_independent/gs25_stock_state.json`)와 분리한다. 건강 상태 저장 장애는 기존 모니터의 반환값이나 원래 예외를 바꾸지 않는다. 저장 손상은 감지 사유를 남기고 건강 상태 기록만 재생성한다. 다른 브랜드 상태와 과거 운영 수량은 배포 커밋에서 변경하지 않는다.

새로운 Telegram 건강 상태 알림이나 웹페이지 연동은 포함하지 않았다. 기존 재입고 알림은 그대로 동작한다. 미확인 점포의 복구는 기존 조회 경로에서 실제 정상 응답이 확인됐을 때 기록한다.
